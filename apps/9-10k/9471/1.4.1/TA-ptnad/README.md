# Official PT NAD Technology Add-on for Splunk

Version: 1.4.1

Author: Sina Mohebi  
Company: Positive Technologies  
License: Apache License 2.0

The Official PT NAD Technology Add-on for Splunk parses, normalizes, searches,
and visualizes RFC 5424-compatible syslog messages generated by Positive
Technologies Network Attack Discovery (PT NAD).

## Features

- Parsing for PT NAD attacks, activities, indicators of compromise, and audit events.
- JSON field extraction for newly indexed events.
- Search-time parsing of historical syslog-wrapped events.
- Normalized source, destination, user, severity, status, and signature fields.
- Splunk CIM event types, tags, and fields for Intrusion Detection, Alerts,
  Authentication, and Change data models.
- Combined-event parsing for incident payloads that contain multiple rule objects.
- Correlation identifiers and multivalue rule identifiers/names for customer-built detections.
- Event types for attacks, incidents, activities, indicators of compromise,
  authentication, changes, and audit events.
- A PT NAD Security Overview dashboard for operational and security monitoring.
- Support for events up to 70,000 bytes, covering the PT NAD 64 KB maximum message size.

## Supported message families

- Attack: `syslog_notifier.alert`
- Activity: `syslog_notifier.detection`
- Indicator of compromise: `syslog_notifier.reputation`
- Audit: `syslog_notifier.audit`

## Supported sourcetypes

- `pt:nad:syslog` — canonical sourcetype
- `pt:nad:syslog2` — compatibility with earlier deployments

## Requirements

- Splunk Enterprise 9.x or 10.x
- A TCP syslog path from PT NAD to the Splunk parsing tier
- The `ptnad` index, created and enabled before data collection begins
- Administrative access for installation and input configuration
- The latest Splunk Common Information Model Add-on compatible with the target
  Splunk environment, when CIM data models or Splunk Enterprise Security are used

## Installation

1. Create and enable an index named `ptnad` under **Settings > Indexes**.
2. In Splunk Web, go to **Apps > Manage Apps > Install app from file**.
3. Upload `TA-ptnad-1.4.1.spl` and restart Splunk if prompted.
4. Create a TCP input under **Settings > Data inputs > TCP**.
5. Assign the input to the `ptnad` index and the `pt:nad:syslog` sourcetype.
6. Configure PT NAD to send matching TCP syslog traffic to the Splunk receiver.

Example Splunk input settings:

- Protocol: TCP
- Port: `5514`
- Allowed sender: `PT_NAD_IP_ADDRESS` (replace with the actual PT NAD address)
- Source: `ptnad:5514`
- Sourcetype: `pt:nad:syslog`
- Index: `ptnad`
- Host method: IP

Example PT NAD recipient:

```text
tcp://SPLUNK_SYSLOG_RECEIVER_IP:5514
```

Replace `SPLUNK_SYSLOG_RECEIVER_IP` with the actual Splunk syslog receiver
address. No environment-specific address is included in this package.

The equivalent documented `inputs.conf` stanza is available in
`README/inputs.conf.example`. The example is not loaded automatically.

## Extracted and normalized fields

The add-on removes the syslog wrapper from newly indexed events, preserves the
JSON body in `_raw`, and enables JSON extraction with `KV_MODE=json`.

Important source fields include:

- `hostname`, `flow_id`, `flow_url`, `identity_key`
- `src.ip`, `src.port`, `dst.ip`, `dst.port`
- `alert.s_id`, `alert.s_msg`, `alert.s_cls`, `alert.s_pr`
- `alert.att_ck{}`, `rpt{}.where`, `rpt{}.type`

Normalized fields include:

- `nad_event_type`, `combined_event`, `nad_correlation_id`, `rule_count`
- `related_rule_id`, `related_rule_name`, `severity`, `severity_id`
- `src`, `src_ip`, `src_port`
- `dest`, `dest_ip`, `dest_port`
- `signature`, `signature_id`, `category`, `ids_type`, `action`, `transport`
- `user`, `event_name`, `object`, `object_category`, `status`
- `vendor`, `product`, `vendor_product`, `dvc`, `app`, `description`

For audit login events, `details.ip` is normalized into `src` and `src_ip`.

## Splunk CIM mapping

The add-on supplies CIM fields, event types, and tags for these datasets:

- PT NAD attacks: **Intrusion Detection / IDS_Attacks** using `ids` and `attack` tags.
- PT NAD activities, IoCs, and combined incidents: **Alerts** using the `alert` tag.
- PT NAD login events: **Authentication** using the `authentication` and `default` tags.
- PT NAD administrative changes: **Change** using the `change` tag; account
  changes also receive the `account` tag.

PT NAD is a passive network detection source. Its attack events are normalized
with `action=allowed`, meaning the observed traffic was detected and was not
blocked by PT NAD.

See `README/CIM_MAPPING.md` for the complete mapping, combined-event contract,
and validation searches.

## Correlation and combined incidents

This TA prepares PT NAD data for correlation but does not ship customer-specific
correlation searches. Detection Engineers build correlation logic in Splunk ES
or Splunk Security Essentials according to the customer's environment.

The TA parses single-rule PT NAD `alert` objects and combined payloads containing
`incident_id` and one of the following arrays:

- `alert[]`
- `alerts[]`
- `rules[]`

Combined payloads produce `combined_event=1`, `nad_event_type=incident`, a
`rule_count`, multivalue `related_rule_id` and `related_rule_name` fields, and a
`nad_correlation_id`. The TA does not combine separate syslog events itself;
PT NAD or an upstream integration service must generate the combined JSON event.

Automated response playbooks and customer-specific correlation searches are not
included in this TA. No Vectra integration implementation, configuration, or
confidential mechanism is included.

## Asset framework scope

The TA does not synchronize PT NAD asset discovery with the Splunk ES Asset and
Identity Framework. It also does not populate ES-managed enrichment fields such
as `src_priority`, `dest_priority`, `src_bunit`, or `dest_bunit`. Splunk ES can
enrich the normalized `src`, `src_ip`, `dest`, and `dest_ip` fields from the
customer's existing asset sources.

## Validation search

```spl
index=ptnad (sourcetype="pt:nad:syslog" OR sourcetype="pt:nad:syslog2")
| table _time nad_event_type combined_event nad_correlation_id rule_count related_rule_id severity action category ids_type dvc src src_port dest dest_port signature signature_id vendor_product
```

## Historical event parsing

Events indexed before installation may retain the syslog wrapper. The included
`ptnad_parse_historical` macro parses historical and newly indexed events in the
same search:

```spl
index=ptnad earliest=0 latest=now
| `ptnad_parse_historical`
| table _time nad_event_type severity hostname user event_name status src_ip src_port dest_ip dest_port signature signature_id flow_url
```

The macro does not modify or reindex historical data.

## Dashboard

The **PT NAD Security Overview** Classic Simple XML dashboard includes:

- Event, attack, severity, source host, and destination host KPIs
- Dangerous attacks and attack timeline
- Attacker and victim hosts
- Client-server pairs and application-layer protocols
- Attack classes and MITRE ATT&CK techniques
- Detected activities, indicators of compromise, and audit activity
- Recent attacks with PT NAD flow links

The dashboard searches the fixed `ptnad` index and supports time, event type,
severity, source IP, and destination IP filters.

## Distributed deployment

- Standalone Splunk Enterprise: install the package on the standalone instance.
- Distributed Splunk Enterprise: deploy index-time parsing settings to the first
  full parsing tier and search-time settings to every relevant search head.
- Heavy forwarder syslog collection: install the add-on on the heavy forwarder
  and on the search head.
- Indexer cluster: distribute the add-on through the cluster manager according
  to the standard Splunk cluster deployment workflow.

Do not configure the same TCP port on multiple Splunk processes on one host.

## Troubleshooting

Confirm that the index exists and is enabled:

```spl
| rest /services/data/indexes
| search title="ptnad" disabled=0
| table title disabled currentDBSizeMB totalEventCount
```

Check the effective configuration:

```text
$SPLUNK_HOME/bin/splunk btool props list pt:nad:syslog --debug
$SPLUNK_HOME/bin/splunk btool props list pt:nad:syslog2 --debug
```

Check for incoming events:

```spl
index=ptnad earliest=-15m
| stats count by host source sourcetype
```

If events arrive without fields, verify that the add-on is installed on the
parsing tier and search head. Index-time corrections affect only new events;
use `ptnad_parse_historical` for existing events.
