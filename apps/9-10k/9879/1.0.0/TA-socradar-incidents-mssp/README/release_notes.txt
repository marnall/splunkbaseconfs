Version 1.0.0
--------------
- First release of the MSSP variant of the SOCRadar Incidents add-on. Use this add-on when you
  monitor several SOCRadar companies from one Splunk deployment; for a single company, use the
  standard SOCRadar Incidents add-on instead.
- Uses the SOCRadar Multi-Tenant Incidents API: ONE input, with your MSSP API Key and your
  Multi-Tenant ID, collects every company you are entitled to. There is no per-company
  configuration.
- The company comes from each alarm itself. Every indexed alarm carries "company_id" and
  "company_name" as SOCRadar reports them, so alarms can be grouped, filtered and reported on
  per company. If SOCRadar sends no company name, the company ID is shown instead. An alarm that
  arrives without a company is indexed as company_id=UNKNOWN so it stays visible instead of
  disappearing from company-grouped panels.
- New "MSSP Overview" dashboard: company count, alarm totals, open and critical/high counters,
  alarms per company, severity mix per company, alarm trend per company, top alarm types per
  company and a per-company breakdown. Company and Severity filters accept a comma-separated
  list, or * for all.
- The Overview and Investigate Alarm dashboards carry a Company column, and Overview has a
  Company filter so a single company can be combined with the tag, main type and sub type
  filters. It accepts a comma-separated list, or * for all. Each entry matches the company name
  or the company ID.
- Overview and Investigate Alarm counts are consistent at any volume: Total and the risk level
  and type charts count every matching alarm; the detail tables list the newest 1,000.
- Trend charts are time-zone independent: an alarm is placed by its SOCRadar date in UTC, not
  re-read in the viewing user's time zone. Date columns are labelled "(UTC)".
- "Manage Alarm Status" has a Time Range input. The alarm table, the Current Status panel and
  the Company dropdown all follow it, so an alarm older than the default 30 days can still be
  found and updated.
- "Manage Alarm Status" binds the selected alarm's own company: the status change is sent to
  that alarm's company, and is refused outright if the alarm carries no company or no enabled
  Multi-Tenant input is configured.
- A new input's Index field starts on socradar_incidents_mssp, the index every bundled
  dashboard reads, so data does not land in main by default.
- The MSSP API Key field of a new input is required and starts empty, so an input cannot
  be saved without a key.
- Changes made on the SOCRadar platform are followed reliably: collected alarms stay
  tracked for 90 days after creation even outside the scan window, a change
  of status, severity, tags or assignees is re-indexed, and the status/tag filters do
  not drop an update to an alarm that was already collected.
- The server-side alarm type filters are verified on every answer; alarms outside the
  requested types are dropped and reported as an error.
- The API key travels in the API-Key request header, never in the request URL.
- The collector writes a warning to its log if two enabled inputs use the SAME Multi-Tenant ID
  in the same index (duplicate alarms; checkpoints are per-input).
- Outbound API calls identify themselves with a product User-Agent
  ("SOCRadar-Splunk-TA-incidents-mssp/<version>"), which helps SOCRadar support trace a
  customer's traffic and lets proxies and firewalls allow the add-on by name.
- Built from SOCRadar Incidents 1.9.30, so it carries that release's collection, filtering,
  IOC enrichment and credential-redaction behaviour.
