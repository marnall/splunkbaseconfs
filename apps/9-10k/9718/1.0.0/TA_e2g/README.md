# E2G Plant Asset Integrity CIM Add-on

## Overview

This Technical Add-on provides search-time CIM normalization for E2G Plant Asset Integrity authentication and audit logs collected from the application database.

The TA supports the following data:

| Log Type | Index | Sourcetype | Database Table | CIM Data Model |
|---|---|---|---|---|
| Authentication / Login | e2g | e2g_authentication | UserAccessLogEntry | Authentication |
| Audit / User Activity | e2g | E2G-Audit | TransactionLog | Change |

## Required Index and Sourcetypes

The following index and sourcetypes are required for the default TA configuration.

**Index:** e2g

**Sourcetypes:**
- e2g_authentication
- E2G-Audit

The sourcetype names must match the values above for the TA configuration to apply.

---

## Data Collection

E2G authentication and audit data is collected from the E2G application database using Splunk DB Connect.

The database collection is configured separately in Splunk DB Connect. This TA handles search-time field normalization and CIM mapping after the data is indexed in Splunk.

| Database Table | Data |
|---|---|
| UserAccessLogEntry | Authentication and user session activity |
| TransactionLog | Audit and user activity |

Database credentials, connection details and DB Connect inputs are not included in this TA.

## Authentication Logs

| Setting | Value |
|---|---|
| Database Table | UserAccessLogEntry |
| Index | e2g |
| Sourcetype | e2g_authentication |
| CIM Data Model | Authentication |

The authentication data contains user login and session activity generated by E2G.

### Event Types

| EventType | Description |
|---:|---|
| 0 | SuccessfulLogin |
| 1 | FailedLogin |
| 2 | UserLogout |
| 3 | ForcedLogout |
| 4 | Timeout |

SuccessfulLogin and FailedLogin events are mapped to the Authentication CIM data model.

UserLogout, ForcedLogout and Timeout events remain searchable in Splunk but are not tagged as authentication attempts.

### Sample Authentication Event

The following sample is synthetic and does not contain production data.

```text
EventTime="2026-01-15 08:30:00.000",
EventType="0",
FirstName="Sample",
LastName="User",
OID="1001",
OptimisticLockField="0",
UserName="sample.user"
```

### Authentication CIM Mapping

| Source Field | CIM Field | Mapping |
|---|---|---|
| UserName | user | E2G username |
| EventType | signature_id | E2G EventType |
| EventType = 0 | signature | SuccessfulLogin |
| EventType = 1 | signature | FailedLogin |
| EventType = 0 | action | success |
| EventType = 1 | action | failure |
| TA assigned | app | E2G |

Source and destination fields are not mapped because this information is not available in the authentication records.

## Audit / User Activity Logs

| Setting | Value |
|---|---|
| Database Table | TransactionLog |
| Index | e2g |
| Sourcetype | E2G-Audit |
| CIM Data Model | Change |

The audit data contains user activity and changes recorded by the E2G application.

Each record can contain one or more entries in AuditLogEntries. These entries contain the attributes involved in the activity and the old and new values where available.

### Sample Audit Event

The following sample is synthetic and does not contain production data.

```text
Timestamp="2026-01-15 09:15:00.000",
OID="10001",
SessionId="10",
UserName="sample.user",
DataItemWrapperOid="20001",
AuditLogEntries="[{
  \"Keyword\":\"SAMPLE_ATTRIBUTE\",
  \"KeywordDetails\":\"SAMPLE_ATTRIBUTE\",
  \"NewValue\":\"20\",
  \"OldValue\":\"10\",
  \"Units\":\"mm\"
}]",
OptimisticLockField="0"
```

### Main Audit Fields

| Field | Description |
|---|---|
| Timestamp | Time of the audit event |
| OID | Audit record identifier provided by E2G |
| SessionId | E2G session identifier |
| UserName | User associated with the activity |
| DataItemWrapperOid | E2G object identifier associated with the activity |
| AuditLogEntries | Contains details of the attributes recorded in the audit event |
| Keyword | Attribute/property recorded in the audit entry |
| KeywordDetails | Additional keyword information provided by E2G |
| OldValue | Previous value, when available |
| NewValue | New value, when available |
| Units | Unit associated with the value, when available |

### Change CIM Mapping

| Source Field | CIM Field | Mapping |
|---|---|---|
| UserName | user | E2G username |
| DataItemWrapperOid | object | E2G object identifier |
| DataItemWrapperOid | object_id | E2G object identifier |
| AuditLogEntries.Keyword | object_attrs | Recorded object attributes |
| TA assigned | change_type | application |
| TA assigned | vendor_product | E2G |

The object_attrs field contains the individual E2G attributes recorded under AuditLogEntries.

When multiple keywords are present in the same audit record, object_attrs is populated as a multivalue field.

Example:

```text
object="20001"
object_id="20001"
object_attrs="FLUID_BASES"
object_attrs="FLUID_COMPONENTS"
object_attrs="FLUID_DEFAULTS"
```

A static action value is not assigned to the parent audit event because a single TransactionLog record can contain multiple audit entries.

## CIM Configuration

The e2g index must be included in the applicable CIM index macros for the events to be returned through the corresponding CIM data models.

### Authentication

Add index=e2g to:

**cim_Authentication_indexes**

### Change

Add index=e2g to:

**cim_Change_indexes**

This TA does not modify the CIM index macros automatically.

---

## Validation

### Authentication Events

```spl
index=e2g sourcetype=e2g_authentication tag=authentication
| stats count by EventType user action signature
```

### Authentication CIM

```spl
| tstats summariesonly=f count
  from datamodel=Authentication.Authentication
  where sourcetype=e2g_authentication
  by Authentication.user
     Authentication.action
     Authentication.app
     Authentication.signature
     Authentication.signature_id
```

### Audit Events

```spl
index=e2g sourcetype="E2G-Audit" tag=change
| table _time UserName user DataItemWrapperOid object object_id object_attrs
```

### Change CIM

```spl
| tstats summariesonly=f count
  from datamodel=Change.All_Changes
  where sourcetype="E2G-Audit"
  by All_Changes.user
     All_Changes.object
     All_Changes.object_id
     All_Changes.object_attrs
     All_Changes.change_type
     All_Changes.vendor_product
```

## Log Coverage

The following logging is currently available from the E2G application:

| Log Type | Status | Source / Details |
|---|---|---|
| Authentication / Login | Available | UserAccessLogEntry |
| Audit / User Activity | Available | TransactionLog |
| Authorization / Role Changes | Not logged | Not available from the application |
| Configuration Changes | Not logged | Not available from the application |
| Data Access Logs | Not logged | Not available from the application |
| Scheduler / Job Logs | Not logged | Not available from the application |
| Performance / Resource Logs | Not logged | Not available from the application |
| Transaction / Business Process Logs | N/A | Not applicable |
| API / Integration Logs | N/A | Not applicable |

Error and exception information may be available through application events but is not currently normalized by this TA.

## Installation

Install the TA on the Splunk search tier where CIM normalization is required.

For a Search Head Cluster, deploy the TA through the SHC deployer.

TA structure:

```text
TA-e2g/
├── README.md
├── default/
│   ├── app.conf
│   ├── eventtypes.conf
│   ├── props.conf
│   ├── tags.conf
│   └── transforms.conf
└── metadata/
    └── default.meta
```

After deployment:

1. Confirm the TA is deployed to the search heads.
2. Ensure index=e2g is included in the Authentication and Change CIM index macros.
3. Run the validation searches above.
4. Confirm Authentication and Change data model results are returned.

## Notes

- This TA performs search-time field normalization and CIM mapping.
- Authentication data is collected from UserAccessLogEntry.
- Audit/user activity data is collected from TransactionLog.
- Database collection is handled through Splunk DB Connect.
- Database credentials and connection details are not included in this TA.
- Sample events are synthetic and do not contain production data.
